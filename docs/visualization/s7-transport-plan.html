S7 — SPIFFE-native transport everywhere

What runs today, where the identity story breaks, and the changes I want to make. Simplified for legibility: telemetry fan-out and replication are drawn as one cluster each.

SPIFFE mTLS (workload SVID) Linkerd mTLS (the mesh's identity) plaintext / unencrypted planned (S7)

Today

  1. The browser edge is plaintext. Kind reaches the API through kubectl port-forward. The chart supports ingress TLS (ingress.tls.*) but nothing ever runs it, so the one hop with real user tokens is the one hop with no encryption.
  2. Two identity systems. Linkerd has an identity for every hop; SPIFFE has one for agent↔gateway. Neither is authoritative at the application layer, and a hop "being encrypted" says nothing about who the peer is.
  3. SPIFFE stops at the gateway. tools, api, sandbox and the third-party systems have no SPIFFE identity. The tool server is a policy enforcement point that never learns the caller's workload identity from the transport — only from a JWT.
  4. No per-hop identity assertion. tls-check.sh asks Linkerd whether an edge is encrypted. Nothing asserts "this hop's peer is the agent's SVID", so any pod the mesh trusts can reach tools directly.

After S7

A consequence worth naming: turning the mesh off for our pods means Prometheus can no longer scrape them over mesh mTLS, so /metrics moves to a plaintext management port — non-sensitive, internal, and documented rather than quietly exposed.

The actions I want to take

  1. A · app/common/server.py — one shared runner that builds an SSLContext from the workload's X.509-SVID, requires a client certificate and verifies the chain. Extracted from gateway/run.py so there is a single implementation, and gated on an env var so a local run stays plaintext. (the file the backlog names doesn't exist yet — this creates it)
  2. B · serve SPIFFE, assert the peer — api, tools, agent run with that context; our clients present SVIDs (agentnhi.mtls_client_context already exists); each server allows exactly one peer identity rather than any valid certificate. Resolves ③ and ④.
  3. C · stop wrapping our pods in the mesh — linkerd.io/inject: disabled on our Deployments, mesh retained for third parties and the vendor stand-in. This is what actually retires the second identity, and it forces the /metrics decision above.
  4. D · the browser edge — an ingress in kind with a TLS cert, so the chart's ingress.tls is the documented path and the exercised one. Independent of A–C; its own PR.
  5. E · prove it — tls-check.sh gains a per-hop SPIFFE assertion: dial each hop with a client SVID, print the peer identity, and fail if a hop we own is not SPIFFE. That is the slice's "Verified by".
